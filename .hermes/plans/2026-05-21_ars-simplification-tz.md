## 0. Проблема (Executive Summary)

Текущий ARS-пайплайн — **полный порт** Claude Code-версии (38 агентов, 10 Kanban-карточек, 81 reference-файл, 19 шаблонов). При прогоне на статье «LLM в Яндекс.Директ» (85 КБ, 346 строк) задействовано ~20% агентов, ~10% референсов. Остальное — шум, раздувающий время прогона с ~40 минут до ~3+ часов.

**Главная причина:** Kanban-оркестрация на 10 карточек — каждая карточка платит полную стоимость сессии (загрузка профиля, прогрев модели, workspace GC). В Claude Code версии все агенты бежали в одной сессии с переключением persona (лёгкое, быстрое). У нас — 10 отдельных рейсов.

**Цель ТЗ:** снизить время получения готовой статьи с 3+ часов до 30-45 минут без потери качества.

## 2. Целевая архитектура: «Мгновенная статья» (Instant Paper)

### 2.1 Концепция

Один запуск → одна комплексная задача → готовый файл.

Никаких промежуточных Kanban-карточек, ручных чекпоинтов, переключений профилей.

### 2.2 Схема работы

```
Пользователь: «Напиши статью на тему Х»

  ↓

[1. Hermes Agent (текущая сессия)]

  ↓ delegate_task(web + terminal) — 1 вызов

[2. bibliography_agent] → 5-10 источников, каскадный поиск
       ↓ (результат — summary + список ссылок)

  ↓ (прямая передача, без файлов)

[3. draft_writer_agent] → черновик статьи, APA 7.0, 2000-5000 слов
  Включает: аннотацию, введение, структуру, выводы
       ↓ (результат — текст статьи)

  ↓ (LLM-обработка, без файлов)

[4. editor_review] → 3-5 замечаний, accept/minor/major
  (один агент, голосовая ревью)

  ↓

[5. Финальная доработка] → исправление замечаний
       ↓

[6. Запись файла] → article.md на Desktop (через execute_code)
```

### 2.3 Почему это быстрее

| Фактор | Сейчас | После |
|--------|--------|-------|
| Загрузка профиля/модели | ×10 (каждая карточка) | ×1 (один раз) |
| Передача контекста | файлы → research_artifacts → GC | прямая передача (delegate_task) |
| Запуск агентов | 10 карточек × N агентов | 3 delegate_task |
| Время простоя | ожидание gateway, kanban-очереди | нет очереди |
| Ручные чекпоинты | T5, T8 — человек вводит accept | чекпоинт — согласие на начало |
| **Итого оценка** | **3+ часа** | **30-45 мин** |

### 2.4 Качество статьи

Упрощение архитектуры **не уменьшает качество**, потому что:

1. Все агенты — это LLM-промпты. 5 агентов получат больше контекста от автора (тема, стиль, объём), чем 38.
2. Draft_writer + одна ревью — тот же результат, что цепочка из 6 агентов (cleaner prompt beats longer pipeline).
3. Прямая передача данных (через Python-переменные) точнее, чем через файлы (`summary` от delegate_task).

## 3. Детальный план упрощения

### Фаза 1: Новая SKILL.md (core pipeline)

Создать упрощённую версию SKILL.md, где:

**Режимы:**
- `instant` (режим по умолчанию) — 3 шага, ~30 мин
- `full` (оставить для больших работ) — 5 шагов, с расширенным ревью
- `legacy` (полный Kanban-пайплайн) — для обратной совместимости

**Instant-пайплайн:**

```python
# Код в SKILL.md (один блок, никаких Kanban-карточек)
def instant_paper(topic: str, style: str = "academic"):
    # Шаг 1: исследование
    sources = delegate_task(
        goal="Найди 5-10 источников по теме",
        context=f"Тема: {topic}\n{source_search_strategy}",
        toolsets=["web"],
    )
    
    # Шаг 2: написание
    draft = delegate_task(
        goal="Напиши статью по теме",
        context=f"Тема: {topic}\nИсточники: {sources['summary']}\n"
                f"Формат: APA 7.0, 2000-5000 слов\n"
                f"Структура: Title, Abstract, 1.Введение, 2.Обзор, "
                f"3.Методология, 4.Результаты, 5.Обсуждение, "
                f"6.Заключение, Список литературы",
        toolsets=["web"],
    )
    
    # Шаг 3: ревью
    review = delegate_task(
        goal="Проведи рецензию статьи",
        context=f"Статья:\n{draft['summary']}",
        toolsets=[],
    )
    
    # Шаг 4: доработка (при необходимости)
    if "major" in review['summary'].lower() or "reject" in review['summary'].lower():
        draft = delegate_task(
            goal="Доработай статью по замечаниям рецензента",
            context=f"Статья:\n{draft['summary']}\nРецензия:\n{review['summary']}",
            toolsets=[],
        )
    
    # Шаг 5: запись файла
    save_to_desktop(draft)
    return draft
```

### Фаза 2: Удаление мёртвых агентов

Не физическое удаление, а **реорганизация**:

- `agents/core/` — 3-5 основных агентов (bibliography, draft_writer, editor)
- `agents/situational/` — остальные (research_question, structure_architect, ethics, meta_analysis и т.д.) — используются при `mode=full`
- `agents/obsolete/` — те, чей функционал поглощён (peer_reviewer → editor, argument_builder → draft_writer)

Таким образом:
1. SKILL.md для `instant` загружает только `agents/core/` (3 файла)
2. SKILL.md для `full` загружает `agents/core/ + agents/situational/`  
3. Старые файлы остаются, но не мешают

### Фаза 3: Чистка reference-файлов

Остальные переместить в `references/archive/` (не удалять физически — вдруг пригодятся).

### Фаза 4: Упрощение профилей

Вместо 4 профилей → 1 профиль `ars-agent` (или использовать default).

**Почему это безопасно:**
- Один профиль = одна установка скилла
- Все агенты внутри delegate_task — не нужно переключать профили
- Herus agent в основной сессии сам решает, какого агента вызвать

**Что изменится в конфиге:**
```yaml
# Было: 4 профиля × N настроек
profiles:
  ars-researcher: ...  # удалить
  ars-writer: ...      # удалить
  ars-reviewer: ...    # удалить
  ars-orchestrator: ... # удалить

# Стало: 1 профиль (или default)
profiles:
  ars-agent:
    skills: [academic-research]
#  или просто использовать default
```

### Фаза 5: Исправление GC и доставки файлов

Проблемы, которые решаются автоматически:
- **GC** — не будет, потому что нет смены Kanban-карточек
- **Desktop** — через execute_code (Python) вместо bash-команд

Дополнительно: сохранять статью в:
1. `~/Desktop/СТАТЬЯ_<тема>.md`
2. `~/academic-research-skills/outputs/` (копия в репо)

### Фаза 6: Тестирование

1. Smoke-test: `instant` → статья по маркетингу → 30 мин
2. Сравнение с результатами пайплайна: та же тема → сравнить качество
3. Edge cases: пустая тема, тема без русских источников, очень длинная тема
